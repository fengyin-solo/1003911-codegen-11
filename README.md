# 地质灾害隐患点监测防治管理系统

面向地质灾害隐患点形变裂缝观测、雨量预警、避险搬迁安置与治理工程验收全流程的地质灾害防治数字化管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `geohazard-monitor-prevention:entries` 这一项，或调用 `resetModule(模块)`。

## 监理交换箱

治理工程的监理协同流程，编排逻辑集中在 `frontend/src/api/exchange-service.ts`，串起三处数据流：
**治理工程（项目）→ 监理交换箱（资料包）→ 工程验收（验收预清单）**。

1. **建包（本端）**：在「治理工程」勾选项目，点「生成监理交换包」，每个项目生成一条
   「待补影像+进度包」交换记录（状态：待回传），同时记下项目状态快照与快照时间。
   已有未核销批次（待回传/已回传）的项目自动跳过，不重复建包。
2. **回传（监理端）**：在「监理交换箱」对单条记录「登记回传」填写现场索引，或「导出交换包」
   拿到 JSON 后线下填写、再「上传回传包」整包导入（状态：已回传）。
3. **核销（平台）**：对已回传批次点「核销整包」，整包核对通过后一次落库：交换记录转
   「已核销」、项目状态与合同金额按规则更新，并同步在「工程验收」生成该项目的
   验收预清单（已存在的项目不重复生成）。

规则约定：

- **状态冲突以时间较晚者为准**：回传的项目状态与平台当前状态不一致时，比较监理回传时间与
  平台快照时间，回传时间更晚则采用回传值，否则保留平台值；裁决结果写入该条的「核对结果」。
- **缺合同金额按未审价带入**：存量项目没有合同金额的，建包快照与核销落库时都记为「未审价」。
- **提交原子化**：核销先整包核对（未回传、缺现场索引、回传状态非法、项目已不在台账等），
  任一不通过则整包不落库；全部通过才用 `saveMany` 把交换箱、治理工程、工程验收三个模块
  一次写入。
- **重复上传仅保留一个批次**：回传包按批次编号+项目编号对账，已回传/已核销的记录视为重复
  上传直接忽略；已核销批次不允许再次核销。
